# libgnss++ v0.4.0

This release brings the native GSDC 2023 smartphone pipeline to its best
recorded score, adds an urban RTK preset and real-time receiver and stream
robustness, and makes the RTK + IMU path (`gnss fuse --base`) a library class.
It also removes a large amount of dormant research code. The
library/CPack/CMake package version is 0.4.0. Most new behavior is opt-in; the
default changes are listed below.

## Highlights

- **Smartphone GNSS/IMU (GSDC 2023-2024).** The official native recipe is
  pinned to submission 57742915: **Private 0.714 m / Public 0.732 m**. This was
  a late submission.
  - It adds a cross-track road prior built from train ground truth, course
    attitude seeds, a third pass on selected drives and a train-fixed
    per-drive variant rule.
  - The variant types were chosen after earlier per-drive Kaggle probes. The
    README states how the score was reached.
  - `gsdc-official` in [the reproduce guide](../reproduce.md#gsdc-official-rebuilding-the-kaggle-submission) rebuilds it bit
    for bit.
- **Urban RTK.** `gnss solve --preset urban` (also accepted by `gnss live` and
  `gnss replay`) on UrbanNav Tokyo Odaiba, against RTKLIB demo5 b34k, both
  multi-GNSS:
  - 7467 vs 5839 fixes;
  - 9/0/0 vs 19/4/4 wrong fixes beyond 0.5/2/3 m;
  - lower horizontal median and P95 error.

  New opt-in fix-recovery controls:
  - Kalman hold-ambiguity update, optionally limited to validated fixes;
  - `--min-fix-satellites`;
  - hold-fix fallback limits (minimum matched pairs, unchanged set, NIS);
  - motion-compensated jump and FIX-history checks;
  - a road-surface height prior (`--road-height-map`).
- **Real-time and receivers.**
  - `gnss live` gains opt-in modes:
    - `--stall-timeout-ms` watchdog and reconnect;
    - `--base-outage-fallback spp`;
    - causal `--kinematic-post-filter`;
    - `--pos-fix-diagnostics`.
  - Multi-constellation MSM epochs are assembled correctly.
  - RTCM ephemerides for Galileo, BeiDou and QZSS: decode 1042/1044, encode
    1042/1044/1045/1046 (`--eph-systems`).
  - Broadcast ephemerides from UBX-RXM-SFRBX: `gnss live --ubx-nav`,
    `gnss convert --nav-rinex-out`.
  - New tools: `gnss realtime-stress`, a recorded-data stress harness, and
    `gnss rtcm-encode`.
- **Uncertainty.** Opt-in per-epoch uncertainty columns in `.pos`, and
  `gnss uncertainty-eval` to score them.
- **RTK + IMU.**
  - `gnss fuse --navi776-tc` with `--base` writes `--out` from an independent
    loose output filter. That filter is fed the RTK position and the epoch SPP
    Doppler velocity, so `--out` is usable under tight coupling.
  - `--consider-before-heading-latch` is new.
  - The per-epoch RTK + IMU pipeline is now `libgnss::RtkImuFusionProcessor`
    (`include/libgnss++/fusion/rtk_imu_fusion.hpp`). The move kept every
    `gnss fuse --base` mode byte for byte.
- **CLAS and MADOCA.**
  - CLAS opt-ins: claslib-style SPP seed residual exclusion, Galileo rows in
    the kinematic filter (`GNSS_PPP_CLAS_GALILEO`) and a stricter first-fix
    F-test (`GNSS_PPP_CLAS_FIRST_FIX_AR_ALPHA`).
  - The MADOCA per-frequency path follows MADOCALIB's innovation gate and
    post-fit screening.
  - MADOCA continues without L6D outside its coverage.

## Default behavior changes

- `gnss fuse --navi776-tc --base` writes `--out` from the independent output
  filter (opt out with `--no-independent-output-filter`). The pre-latch
  re-alignment and the yaw-variance cap also change that `--out`. The RTK
  stream (`--rtk-pos-out`) is unchanged by these.
- The Tokyo PPC lever arm in the urban RTK + IMU recipe, guides and example
  config, and the Nagoya PPC lever arm in `ppc-native-replay` and
  `pva-replay`, are given in body FLU.
- Same-toe ephemeris ties are broken deterministically (Galileo I/NAV first).
- The MADOCA per-frequency PPP path changes as described above.
- Position covariance in ROS 2 `NavSatFix` and the accuracy helpers is
  reported in the local ENU frame.

## Removed

These had no reference anywhere in the repository (docs, scripts, configs,
tests) or could no longer be enabled. Scripts that pass any of them now fail
with an unknown-option error.

- `gnss fuse`:
  - unreferenced options: `--tight-dd-sse-csv`, `--prefer-trusted-seed`,
    `--rover-seed-pos`, `--derive-velocity-from-fixed`,
    `--integrity-fixed-velocity`, `--tc-trusted-reanchor[-max-epochs]`,
    `--tc-cp-pr-gate`;
  - the `--library-fix-integrity-gate` family;
  - `--heading-latch-direction-regression`.
- `gnss solve`: the LAMBDA SRC-PAR/satellite-PAR/WL-NL shadow options, the
  safe-fix shadow and consensus options, and `--library-fixed-quality-*`.
  `--debug-epoch-log` drops the matching always-default columns.
- Library: the fixed-quality gate, consensus state machines, external
  evidence API, the LAMBDA shadow diagnostics and their headers.
- Executables: `gnss_doppler_contract_audit`,
  `gnss_doppler_row_attrition_audit`, and the No-Go smartphone candidates
  `gnss_fgo_imu_v21` and `gnss_fgo_imu_v3_heading_optional`.
- Subcommands:
  - `smartphone-wls-position-eval`;
  - `smartphone-wls-residual-eval`;
  - `smartphone-wls-residual-v2-eval`;
  - `smartphone-wls-stability-selector-eval`;
  - `smartphone-observable-error-correction`.

Their freeze and result records under `docs/use_cases/records` stay; the
sources remain in git history.

## Get started

```sh
docker run --rm -v "$PWD/output:/workspace/output" \
  ghcr.io/rsasaki0109/gnssplusplus-library:v0.4.0 \
  demo --output-dir /workspace/output/self-contained-demo
```

The demo is an offline plumbing check, not a field-accuracy claim.

## Distribution

As in v0.3.0, release automation builds tag-matched TGZ/DEB packages for
Ubuntu 24.04 amd64, installs the DEB in a fresh container before publishing,
and attaches `SHA256SUMS`. The versioned GHCR image includes Python, NumPy and
Matplotlib. See the [release runbook](../release_runbook.md).

## Accuracy and validation scope

The PPC, UrbanNav and SmartPNT runs used during development are development
data, not holdouts, except where a record names a frozen holdout. Ground truth
is used only for offline scoring. Several candidates evaluated in this cycle
are recorded as not adopted; their records explain why.
