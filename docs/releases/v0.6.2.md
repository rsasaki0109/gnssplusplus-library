# libgnss++ v0.6.2

A packaging release: libgnss++ is now on PyPI as `gnsspp`. Solver code and
results are unchanged from v0.6.1. The library/CPack/CMake package version
is 0.6.2.

```bash
pip install gnsspp
gnss demo --output-dir output/self-contained-demo
```

## pip package

- **`pip install gnsspp`** installs the `gnss` command suite and the
  `libgnsspp` Python module (`import libgnsspp`; the module keeps its name).
- **Wheels** for Linux x86_64 and aarch64 (manylinux_2_28), CPython 3.10 to
  3.14. Other platforms build from the sdist with a C++20 compiler; pip fetches
  CMake and pybind11, and the build downloads the Eigen 3.4.0 headers when
  Eigen is not installed.
- **Contents.** The wheel carries the regular `cmake --install` tree (native
  tools, Python commands, configs, demo fixtures) inside the `libgnsspp`
  package, so `gnss` behaves as in an installed prefix. The C++ SDK (static
  libraries, headers, CMake / pkg-config files) is not in the wheel; use a
  CMake build for C++ integration.
- Runtime dependencies are NumPy and Matplotlib, as for the DEB package;
  `gnsspp[full]` adds the optional pandas, SciPy, Pillow and PyYAML.

See [Install with pip](../python_package.md).

## Build changes

- The C++ SDK install rules are now the `Development` install component. A
  plain `cmake --install` still installs everything.
- New `GNSSPP_BUILD_EXAMPLES` option (default `ON`).

## Distribution

As in v0.6.1: tag-matched TGZ/DEB packages for Ubuntu 24.04 amd64 with
`SHA256SUMS`, and the versioned GHCR image. New: the sdist and wheels on
PyPI, uploaded by `.github/workflows/pypi.yml` with Trusted Publishing. See
the [release runbook](../release_runbook.md).

## Validation scope

- Each wheel is installed in the build container and runs `import libgnsspp`,
  `gnss --help` and the offline `gnss demo`. The demo is a plumbing check,
  not a field-accuracy claim.
- macOS and Windows have no wheels yet; their sdist builds are not run in CI.
